Permission policy overview

Example access model used for this pilot.
AdministratorFull administrative access
Manage users, assign category permissions, configure directory settings, review migration/audit records and authorize bulk communication.
ResearcherCommon Data Bank access
Search and view records according to policy. Upload rights are restricted to categories assigned by an administrator.
Read-onlyView-only access
May search or view permitted records but cannot upload or send bulk communications.
Front-end controls are not security boundaries. Laravel must enforce every role and permission on the server for every API request.

Upload permission principles

Recommended rules for implementing category-based access.
Admin assigns one or more categories
Examples: Cotton, Handloom, Silk, International Trade or Research & Reports.
Backend validates every upload
Reject unauthorized categories server-side, even if someone changes browser code.
Bulk email requires a separate permission
Only explicitly authorized users may prepare/send campaigns, subject to policy and approval workflow.
Deactivation preserves user history
Existing uploads and audit history should remain; deactivated accounts cannot sign in.
